WORKFLOW & ACTUAL RUN

從 Wiki 到簡報

2026-11-11：先討論初學者需要的範圍，再 ingest、查詢、查核並生成。下方保留基線發現的缺漏與修改後的結果。

流程圖

  1. 取得並核對原文
  2. Ingest，建立 Wiki
  3. 依教學問題查詢
  4. 立即檢查概念覆蓋
  5. 編排並產生 HTML
  6. 檢查主張、來源與版面

查詢迴圈：缺少必備概念時，回到 Wiki 依缺少的分類重查，每題最多兩輪，沒有新結果便停止。還是不足，就回來源補資料，暫不產生該份簡報。

產出檢查：完成後確認目前 Wiki 版本、主張 ID、所有來源與連結。若失敗，修正資料或編排再重建。每份原文各自核對，每個教學問題各自查詢。

修正後實際有 2 題觸發重查；五題都通過才進入編排。HTML 使用 Wiki 的主張文字和錨點，不把缺少的概念交給生成器猜測。

反思：查到了，卻沒有查齊

這次最常出問題的是「查詢 Wiki」節點。只看關鍵字重疊，APC 的 C10 會擠掉完成時間 C06；前綴問題也會抓到一般 prefill 說明，漏了效益受限的 C11。這是實際查詢的概念缺漏，不是發現兩句假事實。

我把原本「排完草稿才查覆蓋」移到「查到 Wiki 證據後立即檢查」。加入依缺少概念重查的分支，先核對是否具備應教的內容，再產生投影片，減少帶著缺口進入寫作。最終的來源、語意與版面檢查仍保留。

結果只代表本次 5 題與固定 Wiki。規則能核對概念標籤、ID 與版本，不能保證所有摘要都正確；AI 仍要閱讀原文核對語意。互動中的時間數字是教學假設。
